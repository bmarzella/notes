# Semantic Security
Perfect Security is extremely impractical, so we can redefine a weaker definition of security that's actually doable.

Hence, we have **Semantic Security**:
- **Allows negligible information leakage about plaintext.**
	- By negligible, we mean any information leaked gives the attacker a **negligible advantage**; meaning their increase in guessing accuracy beyond a random guess is practically zero (we'll look at this in more detail later).
	- For example, a tiny statistical bias might leak from the ciphertext should not help distinguish between two chosen plaintexts.
- **Enables shorter keys through computational assumptions.**
	- Realistically, if it takes a greater-than-polynomial algorithm to break a cryptosystem, the cryptosystem is secure. 
	- Even if an attacker had a million GPUs, a 128-bit key would require trying $2^{128}$, or $3.4 \times 10^{38}$, combinations.
	- Even the fastest supercomputer we currently have access to would takeover 100 billion years to break it.

> Perfect security requires that, even with infinite computational power, an attacker can glean absolutely nothing about the plaintext from the ciphertext, however little advantage that gives them.
> Semantic security requires that an attacker with a physically plausible amount of computational power cannot glean any information that gives them a *mathematically* significant advantage.

## Semantic Security Games
Recall the **$P$ vs $NP$** problem asks whether every problem whose solution can be **verified** in polynomial time ($NP$) can also be **solved** in polynomial time ($P$).
Recall also that a hard problem is a problem that cannot be solved in polynomial time.

**We cannot formally prove whether a cryptosystem is semantically secure or not, as doing so would imply proving $P \neq NP$** (or more precisely, that one-way functions exist, which is even stronger than proving $P \neq NP$).

> By definition, semantic security requires breaking encryption ($NP$) to be hard to do, but we cannot realistically encrypt something unless it is easy to do ($P$). Therefore, if we could definitively prove a cryptographic system is semantically secure, we would be proving that it is easy to encrypt but hard to break; thereby showing that, for this problem, $P \neq NP$.

So instead, we use **reduction proofs** (which we call games): we prove that if an adversary could break our cryptosystem, they would also be able to solve a mathematical problem that is widely believed to be hard (e.g., Factoring or Discrete Log). Since the math problem is assumed infeasible, the cryptosystem must be secure.
### What is Attacker Advantage
Before we can look at the games, we should understand exactly what Attacker Advantage is. 
1. **Success Rate:** We evaluate the game over multiple runs to find the average probability of the attacker guessing correctly ($\Pr\space[\text{Correct Guess}]$).
2. **Random Guessing (50% Benchmark):** If the attacker is correct close to 50% of the time, they might as well be making completely random guesses, meaning the ciphertext leaks no usable information.
3. **Non-Negligible Advantage:** If their accuracy strays off in **either direction** (mathematically significantly above _or_ below 50%) by a non-negligible amount, they must be gleaning information from the ciphertext:
    - **Above 50%:** They are directly using the leaked information to guess correctly.
    - **Below 50%:** They are still gleaning information, just using it inversely. By simply flipping their guess, they would achieve a high success rate.

>**Advantage is the difference between how often the attacker guesses correctly and a baseline of a random guess, 50%.**

$$\text{Advantage} = \left\vert{} \Pr\space[\text{Correct Guess}] - \frac{1}{2} \right\vert{}$$
For a system to be semantically secure, an attacker's advantage must negligible, effectively 0.
### The Experiment Game

1. **Setup:** The challenger generates a secret key using a uniformly random process.
2. **Selection:** The attacker chooses two plaintexts ($m_0$ and $m_1$) however they wish, subject to one rule: both plaintexts must be of equal length ($|m_0| = |m_1|$).
3. **Challenge:** The attacker hands both plaintexts to the challenger. The challenger randomly picks one of the messages, encrypts it using the secret key, and hands the resulting ciphertext back to the attacker.
4. **Guess:** The attacker analyses the ciphertext and attempts to guess which of the two messages was encrypted and handed back to them.

We measure on average how often the attacker guesses plaintext 1 when given $m_0$ versus when given $m_1$, then find the difference to calculate our advantage.

We run two experiments to cancel out any inherent attacker bias: if their tendency to guess plaintext 1 doesn't change regardless of which message was encrypted, they are gaining zero information from the ciphertext.
#### Mathematical Definition
$$
\begin{array}{l}
\begin{array}{l @{\hspace{4em}} l}
\text{Experiment 0:} & \text{Experiment 1:} \\
1.\ m_0, m_1 \stackrel{\$}{\leftarrow} \mathcal{A} & 1.\ m_0, m_1 \stackrel{\$}{\leftarrow} \mathcal{A} \\
2.\ k \stackrel{\$}{\leftarrow} \mathcal{K} & 2.\ k \stackrel{\$}{\leftarrow} \mathcal{K} \\
3.\ c \stackrel{\$}{\leftarrow} E(k, m_0) & 3.\ c \stackrel{\$}{\leftarrow} E(k, m_1) \\
4.\ \hat{b} \stackrel{\$}{\leftarrow} \mathcal{A}(c) & 4.\ \hat{b} \stackrel{\$}{\leftarrow} \mathcal{A}(c)
\end{array} \\ \\
\hline \\
\text{Adversarial Advantage: } \text{Adv}^{\text{SS}}_{\mathcal{E}}(\mathcal{A}) := \left| \Pr[W_0] - \Pr[W_1] \right| \\ 
\text{where } W_x = \text{event that adversary outputs 1 (guesses plaintext one) in experiment } x.
\end{array}
$$
### The Bit Guessing Game
Instead of running two separate experiments, the bit guessing game happens in one single game where the challenge randomly decides which message to encrypt. We're essentially doing the same thing, but instead of running both plaintexts as different experiments and comparing the results, we just randomly flip between testing each plaintext.

1. **Attacker chooses two plaintexts:** $\mathcal{A}$ generates two plaintexts ($m_0, m_1$) of equal length.
2. **Challenger flips a secret coin:** The challenger picks a secret bit $b$ randomly ($0$ or $1$).
3. **Key generation:** Challenger generates a secret key $k$ uniformly at random.
4. **Encryption:** Challenger encrypts the chosen plaintext $m_b$ (either $m_0$ or $m_1$, depending on the coin flip) to get ciphertext $c$.
5. **Attacker guesses:** Attacker analyses $c$ and outputs their guess $\hat{b}$ for which plaintext was encrypted.
6. **Result:** The game checks if the attacker's guess matches the coin flip ($\hat{b} = b$).
#### Mathematical Definition
$$
\begin{array}{l}
\text{Bit-Guessing Game:} \\
1.\ m_0, m_1 \stackrel{\$}{\leftarrow} \mathcal{A} \\
2.\ b \stackrel{\$}{\leftarrow} \{0, 1\} \\
3.\ k \stackrel{\$}{\leftarrow} \mathcal{K} \\
4.\ c \stackrel{\$}{\leftarrow} E(k, m_b) \\
5.\ \hat{b} \stackrel{\$}{\leftarrow} \mathcal{A}(c) \\
6.\ \text{Return } (b = \hat{b}) \\ \\
\hline \\
\text{Adversarial Advantage: } \text{Adv}^{\text{SS}}_{\mathcal{E}}(\mathcal{A}) := 2 \left| \Pr[W] - \frac{1}{2} \right| \\
\text{where } W = \text{event adversary wins the bit-guessing game.}
\end{array}
$$
## Semantic Security Definition

> ***A cryptosystem is semantically secure if for all efficient adversaries $\mathcal{A}: \text{Adv}^{SS}(\mathcal{A})$ is negligible.***

An **Efficient Adversary** is defined as a **probabilistic polynomial-time (PPT) algorithm**:
- Polynomial time means it is bounded by $O(n^k)$ for some constant $k$, where $n$ is input size. A computation a real computer could finish in a realistic timeframe.
- **Probabilistic** means that, for a given input $x$, random decisions the algorithm makes will result in a different output.
	- By contrast, a deterministic algorithm would always produce the same output given input $x$.
	- We model the adversary as probabilistic because fixed decisions mean they either get stuck making the wrong choice every time, or rely on instantly guessing the key; which would require prior knowledge that defeats the purpose of breaking the cipher in the first place.

**Negligible** is defined as:
$$
f(n) = \mathcal{O}\left(\frac{1}{g(n)} \right ) \text{for super-polynomial g(n).}
$$
*A super-polynomial is a function that grows faster than every polynomial, such as $2^n$.*

As key length $n$ grows, adversary advantage $f(n)$ shrinks faster than any polynomial. i.e., as key length grows, the amount of work required to gain an advantage grows massively, and the advantage gained is less and less significant. With a large enough $n$, it is infeasible to ever gain an advantage at all.

*For whatever reason as I write these notes, my brain doesn't want to understand that advantage doesn't compound. The challenger picks a single $n$, and the adversary has to do work in order to gain an advantage for that specific $n$. Therefore, it's not that we're getting compounding but diminishing returns on advantage, it's that with a high enough $n$, to get any advantage at all requires in inordinate amount of work.*
