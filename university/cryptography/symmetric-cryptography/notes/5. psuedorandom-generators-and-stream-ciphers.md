# Issues with Generating Truly Random Keys
To ensure the security of our system, we want a **truly random key**, however, this is easier said than done.

We rely on a **True Random Number Generator (TRNG)**, a piece of hardware that harvest entropy, such as fluctuations in circuit temperature, and use it to produce truly random bits. However, these physical units can only generate kilobytes per second. For a standard 128 or 256-bit key, that's fine, but what if we need a longer key?

Recall [[3. perfect-cryptosystems#Achieving Perfect Security - One-Time Pad|One-time pad]]. In-order to achieve perfect security, we need a key of length $\geq$ message length. Quickly, this would make TRNGs impractical. We'd have to sit for hours encrypting anything bigger than a few kilobytes. 
# Pseudorandom Generators
Ideally, we'd generate a short, $\ell$-bit seed $s$ as our key using a TRNG, which we then extend into an $L$-bit *keystream*. We abandon perfect security as the key is shorter than the message, but the result is computationally indistinguishable from true randomness whilst being infinitely more practical.

This is exactly what **Pseudorandom Generators (PRG)** do! They take a truly random seed and extend it into a keystream. 

**Formal definition:**
A PRG is a deterministic polynomial-time algorithm $G: \{0,1\}^\ell \to \{0,1\}^L$ with $L > \ell$.
- **Input:** A seed $s \in \{0,1\}^\ell, \text{ (the seed space }\mathcal{S} \text{)}$.
	- Take an $\ell$ bit string of `0`s and `1`s.
- Output: An extended string $y = G(s) \in \{0,1\}^L$.
	- Produce an $L$-bit string of 0s and 1s.
- Requirement: |$L$| > |$\ell$| (expansion)

**Key property:** Output should be computationally indistinguishable from truly random strings.

**No efficient adversary should be able distinguish our keystream $G(s)$ from a truly random seed picked from the seed space $\mathcal{R}$.**
## PRG Security Game
Security is formalised through a distinguishing game where the challenger randomly flips between giving the adversary a pseudorandom keystream $G(s)$ and a truly random string $r$.

1. **Keystream generation:** Challenger picks a secret seed $s$ uniformly at random from seed space $\mathcal{S}$ and computes $r_0 = G(s)$.
2. **Truly random generation:** Challenger samples a truly random string $r_1$ uniformly at random from output space $\mathcal{R}$.
3. **Challenger flips a secret coin:** Challenger picks a secret bit $b$ randomly (0 or 1) to decide which string to test.
4. **Attacker guesses:** Attacker $\mathcal{A}$ receives $r_b$ and outputs their guess $\hat{b}$ for whether they received the PRG keystream ($b=0$) or pure random noise ($b=1$).
5. **Result:** The game checks if the attacker's guess matches the coin flip ($\hat{b} = b$).
#### Mathematical Definition
$$
\begin{array}{l}
\text{PRG Security Game:} \\
1.\ s \stackrel{\$}{\leftarrow} \mathcal{S} \\
2.\ r_0 \leftarrow G(s) \\
3.\ r_1 \stackrel{\$}{\leftarrow} \mathcal{R} \\
4.\ b \stackrel{\$}{\leftarrow} \{0, 1\} \\
5.\ \hat{b} \stackrel{\$}{\leftarrow} \mathcal{A}(r_b) \\
6.\ \text{Return } (b = \hat{b}) \\ \\
\hline \\
\text{PRG Advantage: } \text{Adv}^{\text{PRG}}_G(\mathcal{A}) := 2 \left| \Pr[W] - \frac{1}{2} \right| \\
\text{where } W = \text{event adversary wins the distinguishing game } (b = \hat{b}). \\ \\
\text{Security Condition: } G \text{ is secure if } \text{Adv}^{\text{PRG}}_G(\mathcal{A}) \text{ is negligible for all PPT } \mathcal{A}.
\end{array}
$$
> *We pick a random seed from the seed space, generate a keystream, flip between giving the adversary the keystream or just random noise, and measure their advantage. 
> See [[4. semantic-security#Semantic Security Games|Semantic Security Games]] for more detail on how games and advantage work.*
# Stream Cipher
Stream cipher is cipher that utilises a PRG. It takes a truly random seed, extends it into a keystream, then encrypts plaintext using the keystream.

1. Generate a truly random 128-bit seed $s$ using the TRNG.
2. Use a PRG to extend $s$ into an $L$-bit keystream.
3. `XOR` the keystream with the plaintext to generate a ciphertext.
$$
\begin{array}{l} \\
\text{Stream Cipher:}\\
E(s, m) := G(s) \oplus m \\
D(s, c) := G(s) \oplus c \\ \\
\hline \\
\text{where } G : \{0, 1\}^\ell \to \{0, 1\}^L \text{ is a pseudorandom generator.}
\end{array}
$$
*Encryption function is defined as taking the seed and plaintext, generating a keystream and then `XOR`ing them together. You can figure out decryption ;\)*
## Theorem
*See slide 17*
If we have cipher that is based on a PRG, and we assume the PRG is secure (recall we cannot *prove* this, but if a PRG hasn't been broken after years of attempts and it fits under our PRG games, we can assume it is secure), then we can prove the cipher based on it is semantically secure too.
Breaking the PRG of course means breaking the cipher, but taking the contrapositive of this theorem means that breaking the cipher would also mean breaking the PRG.
### Proof: Game Hopping
We want to show that if there is an adversary with an advantage against my cipher, then there is an adversary with an advantage against my PRG. We do this with something like a reduction, using the advantage definition instead of NP-hardness. 

1. We begin with Game 0, which is just the standard [[4. semantic-security#The Experiment Game|experiment game]]. This tells us the advantage of an adversary against our cipher.
	- $\text{Adv}_{\text{SS}}(\mathcal{A}) = 2 \cdot \left( \text{Pr}[W_0] - \frac{1}{2} \right) = 2 \cdot \text{Pr}[W_0] - 1$, just a way of re-writing out advantage formula.
2. For Game 1, we replace our PRG with a truly random key. Game 1 now depicts a one-time pad, which we know for a fact is perfectly secure, and thus advantage is 0. If we let $W_1$ be the event that the adversary guesses correctly and wins Game 1, then $Pr|W_{1}| = \frac{1}{2}$.
3. We want relate this to Game 0, specifically by finding the change in advantage $|Pr|W_{0} - Pr|W_{1}||$. To do this, we create a new adversary $\mathcal{B}$ who is trying to break the PRG (using the PRG game above) that is used in Game 0.
	- Because the only difference between Game 0 and 1 for $\mathcal{A}$ is whether we are using the PRG or not, then the difference in advantage is equal to $\mathcal{B}$'s advantage against the PRG.
	- So, $\vert{}\text{Pr}[W_0] - \text{Pr}[W_1]\vert{} = \text{Adv}_{\text{PRG}}(\mathcal{B})$.
4. Putting this all together:
$$\text{Adv}_{\text{SS}}(\mathcal{A}) = 2 \cdot \left\vert{} \text{Pr}[W_0] - \frac{1}{2} \right\vert{} = 2 \cdot \vert{}\text{Pr}[W_0] - \text{Pr}[W_1]\vert{} = 2 \cdot \text{Adv}_{\text{PRG}}(\mathcal{B})$$
Since the PRG is assumed to be secure, $\text{Adv}_{\text{PRG}}(\mathcal{B})$ must be negligible, which means $\text{Adv}_{\text{SS}}(\mathcal{A})$ must also be negligible, thus the cipher is semantically secure.

> The difference in advantage of an adversary attacking a semantically secure and perfectly secure cipher is equal to the advantage of an adversary against the PRG the cipher is based on. Through this, we derive an equation that shows $\mathcal{B}$'s advantage is half of $\mathcal{A}$'s. We know $\mathcal{B}$'s is negligible, therefore so is $\mathcal{A}$'s. 
# Issues with Stream Ciphers
If an adversary gets two ciphertexts that use the same key, XORing them together gets the XOR of the plaintexts, which reveals a lot of information.
## Malleability
**Malleability** means an attacker can modify a ciphertext so it decrypts to a predictable fake message—all without ever knowing the secret key.
- Stream ciphers use XOR. Flipping a bit in the ciphertext directly flips the exact same bit in the decrypted plaintext.
- If an attacker knows or guesses the original message (e.g., `"attack at dawn"`), they tweak the ciphertext bits so the recipient decrypts it as `"attack at dusk"`.
- Stream ciphers provide **secrecy** (confidentiality), but NOT **tampering protection** (integrity). Without an added authentication tag (like a MAC), the recipient has no way to detect the change.
# Extension
## Parallel
Generate longer keystreams by generating keystreams from independent seeds, then concatenating them together to create one long keystream.
Ratio remains the same, we need to generate more true random numbers using our TRNGs, so this is impractical.
Attacker advantage scales linearly with the number of extensions. If the attacker realises parallel extension was used, they can split the ciphertext into $n$ smaller ciphertexts each with their own key, meaning they have $n$ opportunities to gain an advantage.
## Sequential
Generate longer keystreams using *a single seed.* Use seed to generate keystream, separate keystream into seed and any remaining bits are added to an overall keystream. Run seed bits back through the same PRG to get more keystream and seed bits, repeat until get a long enough final keystream.
roughly linear advantage loss for each link in chain.
Attacker advantage scales linearly with the number of extensions. If the attacker realises sequential extension was used, the keystream is generated through a chain of $n$ step-by-step state updates, giving them $n$ opportunities across the chain to spot non-randomness (and cracking any single seed compromises every future block).
